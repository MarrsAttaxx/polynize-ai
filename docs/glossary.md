# PAM — Glossary

**What this doc is:** the vocabulary of PAM and Polynize — the terms, named systems, and agents a reader (human or agent) will hit and need defined. When START-HERE or another doc uses a term that isn't obvious, it should be here.

**Last updated:** 2026-06-05

---

## Core concepts

**PAM (Polynize Agent Management)** — the system that both runs Polynize as a business and is the delivery product for clients. Manages AI agent teams across the engagement lifecycle.

**Engagement** — a single client project. Four are live: Roxbury, EverStock, Newkind, reMYnd. Each has its own GitHub repo holding its data.

**Engagement lifecycle / phases** — **Modelling → Build → Operate**.
- *Modelling*: analysing the client's business and agreeing scope (pre-build). Three engagements are here (EverStock, Newkind, reMYnd).
- *Build*: building the agent team (active sprint). Roxbury is here.
- *Operate*: the agents are live and running; ongoing tuning/support (post-handoff).

**Blueprint** — the per-engagement analysis: the capability map, benchmarking, uplift plan, next steps, and the team. Rendered in the Console from `capability-map.json` + `engagement-model.json` + the 5 live sections of `blueprint.md`. Has two layers (see architecture.md): the pre-agent *analysis* layer and the downstream *team/work-plan* layer.

**Capability** — a discrete piece of the client's business work (e.g. "social content production", "clinical escalation"). Each is allocated **Human / Hybrid / Agent** and carries a benchmark, uplift plan, completeness, and (for hybrid/human) a human handoff.

**Allocation (Human / Hybrid / Agent)** — how a capability is done. *Human* = a person does it (excluded from agent scope). *Hybrid* = human judgment in the loop each time. *Agent* = an agent runs it end-to-end (a human reviews/approves but isn't in every instance). Agent rows have a null human_handoff; hybrid/human rows carry a handoff object.

**Cluster** — a grouping of related capabilities in the capability map. Each has an `order` and a `cluster_type` (e.g. sequential, parallel, off_cycle).

**Completeness (STUB / PARTIAL / COMPLETE)** — how well-defined a capability's data is, from the source material. Rendered as a labelled meter: STUB → "Needs detail", PARTIAL → "Partly mapped", COMPLETE → "Fully mapped". Currently a *provisional AI judgment* (becomes rigorous when Cognitive Studio / Ben land). Drives Modelling readiness.

**Motions** — the three classes of work that move an engagement forward, in `engagement-model.json`: **Training** (build the human-in-the-loop judgement), **Transform** (stand up process + infrastructure), **Agent Deploy** (deploy the agents). Each lists which capabilities it covers.

**Benchmark / uplift** — per capability: the *benchmark* is "what good looks like"; the *uplift* is the moves to get there, across People (Train) / Process (Transform) / AI (Deploy).

**Readiness** — the engagement's progress percentage, *phase-relative* (Build = work-plan sprint weighting; Modelling = 0.80 × analysis completeness + 0.20 × blocker resolution). See architecture.md / decisions.md D5–D6.

**Gap register** — the table of outstanding questions in `blueprint.md`, split into **Critical Blockers** (gate sign-off) vs **Gaps to resolve in build**, via a per-row Blocking column. See decisions.md D7.

**Sprint stages** — the 8 weighted stages of a Build work plan: Sprint Map → Cognition Design → Skills Design → Cognition Install → Skills Install → Sandbox Testing → Live Testing → Handoff. The sprint ends at Handoff; refinement is post-handoff in Operate.

## The team model

**CWU (Cognitive Work Unit)** — the canonical team shape: **three tiers, always**. Human accountable lead → Team leader agent → Worker agents. See decisions.md D4.

**Team leader agent** — the auto-inserted coordinating agent on every team: coordinates the workers, is the connection point between Polynize / the client / the agent team, the reporting + escalation channel, and the security layer. An additional agent on top of the workers. Must exactly match the `team_leader` string in `capability-map.json`. Live ones: Mable (Roxbury), Scout (EverStock), Don (Newkind), Joy (reMYnd).

**ACTA** — the team-leader's security model: **A**ccess (scoped tool permissions), **C**ognition (programmed do/don't rules), **T**eam-lead (the leader watches the team), **A**mazon (AWS isolation). The team-leader agent embodies the ACTA team-lead role; it's the non-negotiable security layer on every job.

**Human accountable lead** — the client-side human who owns the engagement (e.g. Erfan for Newkind, Naomi for reMYnd, AJ for EverStock, Scott/Jayden for Roxbury).

**Worker agents** — the agents that do the capability-allocated work, under the team leader.

## The SoW (Statement of Works)

**SoW (Statement of Works)** — the commercial agreement for an engagement, generated by merging Blueprint data into a fixed legal template, completed by humans, and signed by the client. Lives in `sow.json`.

**AUTO / HUMAN / STATIC fields** — *AUTO* fills from the Blueprint (≈80% of the body). *HUMAN* are commercial/legal fields not in the Blueprint, filled by a person (rendered as coloured badges). *STATIC* is the Service Agreement boilerplate.

**Mint / Orange (the two-colour fill system)** — *Mint* (#4de8a0, brand colour) = Polynize-owned HUMAN fields. *Orange* = client-owned HUMAN fields (the client's own entity facts). Clients see their orange fields to fill and never see Polynize "to-do" badges.

**Service Agreement** — the static legal boilerplate (clauses 1–25 + schedules) that rides as **Annexure A** to the SoW. "Support" is its defined legal term (distinct from the "Operate" commercial label — see decisions.md D13).

**Send to client** — the team-only action (appears only when all mint fields are filled) that opens a mailto with the SoW link.

**Lock / sign** — a client signs (typed name → cursive), which locks the SoW server-side. Team can unlock (which clears the client signature). See decisions.md D12.

## Named systems & infrastructure

**PAM Console** — the human-facing web app (at pam.polynize.ai), part of the `polynize-ai` project. Renders blueprints and SoWs with role-based access.

**polynize-ai** — the Next.js project that is both the public polynize.ai website and the PAM Console. One Vercel project; deploys on push to `origin/main`.

**Hermes** — the orchestration runtime the production agents run on (AWS Lightsail + Bedrock model routing). *Note:* "Hermes" sometimes appears in client decks as infra-talk — don't confuse it with an agent name (e.g. reMYnd's agent is Joy, not Hermes).

**Cognitive Studio** — Shourov's rigorous transform engine that generates cognition/capability files. The upstream dependency for wiring Ben. Lands ~next week; will export a markdown seed that imports into PAM.

**Ben** — the intended automated transform agent (CS-01, Intelligence Architect) that will ingest transcripts and write Blueprint JSON into engagement repos, replacing the manual emulator builds. Depends on Cognitive Studio.

**Cognitive Studio emulator** — the *interim manual* stand-in for Ben: a fresh Claude chat in an engagement's project, given the canonical schema as a literal template, producing the Blueprint JSON. How all four live blueprints were built. The spec for Ben (see decisions.md D3).

**Hindsight** — the long-term memory substrate for agents (replaced an earlier Neo4j approach).

**Orthogonal** — the skills gateway / marketplace where agents acquire new skills.

**Build Bench** — the intended testing/deployment pipeline (Cognitive Studio → validation + infra selection → Lightsail production), to be orchestrated by R2-D2. Currently run manually for the first client (Roxy) to build the runbook before automating.

**Supabase** — the CRM datastore (the `crm` schema). Cross-schema access is asymmetric: reads use `Accept-Profile: crm`, writes use `Content-Profile: crm`; needs the service-role key (not anon).

**Vercel** — the host for polynize-ai; auto-deploys on push to `origin/main`.

**Resend** — the email service behind the Console's passwordless magic-link sign-in.

**Lightsail** — AWS hosting for the production agents (Hermes runs here).
